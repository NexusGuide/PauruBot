# بازبینی امنیتی پیش از انتشار 0.1.0 — نوامبر ۲۰۲۶

مبنای بازبینی: `a272b82` (پس از ادغام PR #143). هر یافته اول با تستی بازتولید شد که روی کد قبلی شکست می‌خورد. بعد اصلاح شد.

**دامنهٔ بازبینی:**
- **ورود و دسترسی:** ورود کارکنان، کد یک‌بارمصرف، کلید API، بازیابی رمز، نشست و CSRF، و ماتریس نقش‌ها
- **مینی‌اپ:** امضای initData (ربات اصلی و ربات نماینده‌ها)، مالکیت در همهٔ مسیرهای آن، دروازهٔ شماره و قوانین، و ابزار کارکنان در مینی‌اپ
- **پرداخت:** callback درگاه‌ها، Stars، پیامک بانک و چرخهٔ پرداخت
- **مسیرهای عمومی:** لینک اشتراک `/s/…`، خرید مهمان و webhookهای تلگرام و پنل
- **پنل مدیریت:** محدود بودن هر کوئری به فروشگاه خودش و دامنهٔ نماینده
- **ربات:** فیلتر نقش در روترهای مدیریت
- **پول و پاداش:** حذف سرویس با بازپرداخت، انتقال کیف پول، کد هدیه و کد تخفیف، و پاداش دعوت (GRW-11)
- **فرانت‌اند:** نمایش HTML خام و لینک‌ها
- **استقرار:** Dockerfile، Caddy و فایل‌های پشتیبان

بیشتر مسیرهایی که ممیزی‌های اکتبر و نوامبر بستند، بسته مانده‌اند:
- مالکیت هر شناسه در مینی‌اپ و پنل بررسی می‌شود.
- امضا و مبلغ درگاه‌ها تطبیق داده می‌شود.
- callback فقط نشان می‌دهد کدام پرداخت باید بررسی شود. خود پرداخت با پرسیدن از درگاه تأیید می‌شود.
- توکن‌ها آنتروپی کافی دارند.
- خروجی HTML escape می‌شود و CSP سخت‌گیر است.

## موارد بررسی‌شده و سالم

- **initData:** HMAC با توکن ربات اصلی و ربات هر نماینده بررسی می‌شود و فروشگاه از خود امضا تعیین می‌شود. عمر آن ۲ ساعت است. پاسخ امضاشدهٔ `requestContact` به همان کاربر گره خورده است.
- **مالکیت در مینی‌اپ:** سفارش، پرداخت، سرویس، تیکت، پیام تیکت، حساب پنل و میز نماینده همه با `customer_id` و `shop_id` بررسی می‌شوند.
- **پنل مدیریت:** `owned()` و `scope_services()` روی همهٔ جست‌وجوهای شناسه اعمال می‌شوند. عملیات گروهی شناسه‌ها را پیش از هر کاری محدود به فروشگاه و دامنهٔ نماینده می‌کند.
- **نقش‌ها:** کلید API هرگز `staff.manage` یا `panels.secrets` یا `backups.manage` ندارد. مالک فقط هنگام نصب ساخته می‌شود. نقش مالک قابل تغییر نیست.
- **کارکنان در ربات:** نماینده‌ها کارمند ربات حساب نمی‌شوند. هر callback مدیریتی فیلتر دسترسی دارد. وضعیت‌های FSM فقط از همین callbackها قابل رسیدن‌اند.
- **درگاه‌ها:**
  - callback فقط نشان می‌دهد کدام پرداخت را بررسی کنیم. خودِ پرداخت با پرسیدن از درگاه یا با HMAC روی بایت‌های دقیق تأیید می‌شود.
  - شناسهٔ مرجع (authority) با رکورد پرداخت تطبیق داده می‌شود.
  - تراکنش تکراری DISPUTED می‌شود.
- **پیامک بانک:** کلید محرمانهٔ هر فروشگاه لازم است. رد شدن کلید اشتباه برای همه یک پاسخ دارد، و سهمیه فقط پس از کلید درست شمرده می‌شود.
- **لینک اشتراک:** توکن ۱۶ تا ۴۸ کاراکتری با محدودیت درخواست. هدرهای پنل فقط از فهرست مجاز عبور می‌کنند. دریافت لینک‌ها از پشت محافظ SSRF انجام می‌شود.
- **خرید مهمان:** توکن ۱۹۲ بیتی، محدودیت درخواست برای هر IP و فروشگاه، کوکی فرم host-only، و `no-referrer`.
- **فایل‌ها:** فایل پشتیبان فقط با نام معتبر و دسترسی `backups.manage` دانلود می‌شود. پیوست تیکت و رسید دوباره رمزگذاری و بررسی ابعاد می‌شوند.
- **فرانت‌اند:** HTML خام فقط برای آیکون‌های ثابت استفاده می‌شود. لینک‌ها فقط `https://` یا `t.me` هستند، و React 19 لینک `javascript:` را مسدود می‌کند.
